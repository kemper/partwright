## What's working (preserve these)

- **Explore-first / pre-work mapping before implementing** keeps paying off — the part-grouping session found every constraint (schema ladder, both import loops, the NUL-byte caveat, drag internals) already documented before writing a line, and the mesh-to-code session's explore-agent integration map turned every wiring step into a copy-of-a-sibling. This is already CLAUDE.md doctrine; no change needed, just reconfirmed.
- **`model:preview` as the inner verification loop** keeps catching real defects by looking, not guessing (blender-parity's corduroy-terracing defect; catalog-refresh's toadstool spots buried in the cap). Already documented.
- **Parallel disposable subagents keeping expensive iteration out of the caller's context** worked cleanly at two different scales this cycle: `model-sculpt` for 5 showcase catalog models (blender-parity), and 14 `model-sculpt` rework agents aggregated into one structured retro (catalog-refresh) — proof the "delegate multi-pass visual iteration" doctrine scales to fleet-sized batches too.
- **The inverse-CAD PLAYBOOK ratchet continues to compound across sessions and geometry classes** — the armor-era recipe transferred verbatim to a never-seen 3DBenchy mesh and converged in 6 attempts with zero part-specific babying. The "require PLAYBOOK candidates in every subagent return" mechanism is doing exactly what it was designed to do.
- **`work-reviewer` earns its keep**: it caught the one real regression in part-grouping (collapsed groups no-oping all drags) that the author's own e2e hadn't exercised.
- **Measure-the-instrument-first**: the inverse-CAD v2 rebuild's single highest-leverage finding was a 5-line self-distance check exposing a 0.15mm noise floor in the old metric — the user's eye had been right and the number wrong.
- **API design that samples the real built surface instead of hand-derived trig** (scatter's `where(p, n)` predicate) fixed a latent bug for free and drew explicit praise from 4 independent rework agents.

## Top friction (ranked by cross-session frequency × cost)

1. **[tooling] No warm-browser loop for UI (not just model) iteration** — 2 sessions explicit (multi-part-assembly-view, 3mf-packing-strategy — the latter calling it "the same wish as prior retros"), and it's been surfacing across cycles without ever getting built. Every UI-feature round pays a cold ~4s WASM boot + fresh session build inside a throwaway Playwright run; a 5-round UI feature burns minutes of dead wall-clock. The existing `bin/partwright.mjs daemon` only warms the browser for **model geometry** preview (`render`/`iterate`), not for driving UI (clicks, panels, worker pools). **Action: backlog** — a UI-iteration daemon is a real build, not a doc fix.
2. **[geometry QC] Genus/component-count instrumentation gaps recur across unrelated features** — 3 sessions: 3DBenchy had to hand-build `voxelGenus.mjs` mid-task because mesh-genus and solid-genus diverge on self-touching meshes; multipart-kits-overview burned ~8 bake round-trips because `decompose()`, the app's stats count, and a welded-mesh census disagreed on a degenerate mesh; catalog-refresh wanted a genus-change flag after a fin-weld stitch silently went genus 0→10 unnoticed. **Action taken**: added a CLAUDE.md callout (near the existing `componentCount`/`voxelPieceCount` guidance) that self-touching/degenerate meshes make `decompose()` and genus non-deterministic, and that `Mesh.merge()` + `ofMesh` canonicalization must run before any decompose-based filtering. The headless "count it three ways" tool and a genus-change flag are **backlog** (need new stats fields).
3. **[deform API] scatter/round/smoothWeld friction — already tracked as #928, this batch quadruples the vote.** The 16-agent catalog-refresh rework batch independently converged on the same four asks: a `placedCount`/dry-run mode for `scatter` (4 agents), region-scoped `smoothWeld`/`round` instead of whole-bbox (2 agents), a worked numeric example or `seat` convenience for offset-vs-instance-thickness sizing (3 agents), and a documented radius-to-edge-length rule of thumb for thin features (3 agents). `deform.md` was already updated in that batch for the thin-shell caution and two API quirks (paint.slab's one-sided band, circularPattern's origin-relative radius) — those doc fixes are already landed, not this PR's to make. The remaining asks are **API/tooling backlog**, tracked under #928.
4. **[process, already fixed] promptlog-guard "fires too early" reconfirmed post-fix** — part-grouping (2026-07-06) hit the exact "compound `git add -A && git commit` gets denied before add stages the log" issue that 2026-W27's retro already added a CLAUDE.md callout for. The doc fix is correct and current; this is muscle-memory catching up, not a doc gap. No further action.
5. **[inverse-CAD] Orchestration/convergence bookkeeping is the one part of the framework that doesn't scale itself** — 3 sessions (v2, armor-genericity, benchy) each independently wanted a driver/status tool: v2 wanted rate-limit-resilient resumable agents (state files worked, but manually), armor-genericity had a part silently never get assigned an agent (caught only by a final manual sweep — "a `status.mjs` would have shown the hole immediately"), and benchy wanted a convention distinguishing "agent finished" from "best exists" so orchestrators don't consume a moving target. **Action: backlog.**
6. **[tooling gap, corrected] NUL-byte `main.ts` guidance told agents to reach for a `grep -a` flag the dedicated `Grep` tool doesn't have.** The 3mf-packing session burned a call finding this out the hard way. **Action taken**: reworded the CLAUDE.md callout to say explicitly "use the Bash tool with `grep -an`" rather than implying the flag exists everywhere.
7. **[testing, corrected] Rail/list-drag Playwright specs silently miss off-screen rows at the default viewport.** part-grouping burned two runs before realizing the parts rail only shows ~3 rows at 1280×900, so drag targets below the fold aren't just slow to reach — they're not there. **Action taken**: added a numbered gotcha to `docs/playwright-guide.md`.
8. **[export QC] No headless visualization for build-plate/pack layouts.** bambu-plate-layout-packing verified 3MF packing correctness by parsing `<item>` transforms out of the XML and asserting bed-bounds numerically — correct, but nothing showed the *arrangement* the way `model:preview` shows geometry. **Action: backlog** (1 session, but concrete and cheap to build as a sibling to `model:preview`).
9. **[testing] Fixed `waitForTimeout` calls are the traced root cause of two open flaky-shard issues (#911, #912).** 3mf-packing-strategy names both by number and proposes a shared `waitForEngineReady(page)` readiness-poll helper as the general fix. **Action: backlog.**
