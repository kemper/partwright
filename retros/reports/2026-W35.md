## What's working (preserve these)

- **The inverse-CAD PLAYBOOK ratchet** — requiring every convergence subagent to return "new tactics/PLAYBOOK candidates" in its report, then merging them before launching the next wave — is independently praised across all three inverse-CAD entries (v2, armor-genericity, benchy) and is credited with turning 21-, then 16-, then a never-seen foreign mesh into median-one-turn convergence. This is exactly this retro-review's own method (cross-agent frequency as the vote); good confirmation it generalizes.
- **`model:preview` as the fast inner loop for geometry work** continues to pay off — the blender-parity-verbs session caught a corduroy-terracing defect purely by looking at a render, and the catalog-refresh batch's headline result (`round`/`scatter`/`smoothWeld` applied to 16 existing entries by 14 parallel `model-sculpt` subagents, all returning print-valid) is a direct product of the "delegate multi-pass visual iteration" doctrine already in `CLAUDE.md`.
- **Per-part `expectComponents`/`--expect-components` gating** caught three real regressions in one afternoon on the dummy13 multi-part kit work (simplify fusing articulated pieces, sub-mm debris, non-deterministic `decompose()`) — the existing CLAUDE.md guidance to gate on this instead of eyeballing is working as intended.
- **Exploration before implementation** continues to be the difference between a design "falling out immediately" and a rewrite — the part-grouping session found the seven-location schema ladder, both import loops, and the NUL-byte caveat all pre-documented, and `work-reviewer` caught the one regression its own e2e coverage missed.
- **Scatter's `where(p, n)` predicate + deterministic seeds + paint-label survival** were called out by name as API design that "just worked" across cap-only, spine-sparing, sloped-only, and door-sparing placement cases — worth protecting as-is while the harder ergonomics gaps below (placement feedback, offset sizing) get addressed.

## Top friction (ranked by cross-session frequency × cost)

1. **[modeling/deform] Blender-parity verb ergonomics** — scatter placement uncertainty (4 agents: no `placedCount`/dry-run signal), offset-vs-instance-thickness sizing (3 agents), thin-feature radius ceilings sharper than documented (3 agents), `smoothWeld`/`round` lattice-the-whole-bbox cost (2 agents), buried-label surface-exposure blind spot (1 agent, flagged high-value) — all raised in the 16-agent aggregate (`2026-07-20-catalog-refresh-agent-feedback.md`). **No action needed here**: every one of these is already captured in `#928`, which explicitly cites this exact retro file as its vote source. Confirms the issue's priority ordering is right; nothing to add.
2. **[tooling] Inverse-CAD multi-agent convergence runs have no orchestration driver** — 3 independent sessions (v2, armor-genericity, benchy) each hit some flavor of the same gap: a part silently never got assigned an agent (caught only by a manual final sweep), the `Stop` hook fired ~20 times with nothing to reconcile during long agent waits, a subagent's still-polishing "best" got consumed early because there's no "agent finished" vs "best exists" signal, and converged results lived only in gitignored `.plans/` on an ephemeral container until an explicit rescue-copy. Not filed as an issue. See Backlog.
3. **[tooling] No single trustworthy component/topology counter** — 3 sessions (multipart-kits-overview, benchy-foreign-mesh, and one catalog-refresh agent) independently lost time to engine `decompose()`, the app's statsComputation count, and a welded-mesh census disagreeing on degenerate meshes, plus mesh-genus vs. solid-genus diverging on self-touching meshes (had to build `voxelGenus.mjs` mid-task). One session burned ~8 bake round-trips before finding the actual disagreement. Not filed. See Backlog.
4. **[process, applied] `main.ts` NUL-byte grep guidance didn't distinguish the harness's `Grep` tool from Bash `grep`** — a session tried `-a` on the dedicated `Grep` tool (which has no such flag) before falling back to Bash `grep -a`, burning a call CLAUDE.md's existing guidance didn't prevent. **Action:** clarified in CLAUDE.md.
5. **[process, applied] Rail/list drag e2e specs silently miss rows below the fold** — the parts-list panel is a short scroll box at the default viewport; a drag-target assertion on a scrolled-out row no-ops instead of failing loudly, costing two runs + a debug scratch to diagnose. **Action:** added to `docs/playwright-guide.md`'s gotcha list.
6. **[process] Warm dev-server/browser loop wanted for general UI iteration** — 2 sessions (multi-part-assembly-view, 3mf-packing-strategy) each paid a cold ~4s WASM boot + fresh session build per Playwright round for pure UI-wiring changes with no model geometry involved. The model-*render* side of this wish is already solved (`bin/partwright.mjs daemon start`, documented in CLAUDE.md's Headless Model Preview section) — this is the same ask for driving `window.partwright` UI interactions generically. Not filed. See Backlog.
