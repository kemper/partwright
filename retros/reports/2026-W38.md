# Retro Report — 2026-W38

**Entries reviewed:** 12 (from 12 primary sessions; one entry — the catalog-refresh
batch — aggregates structured feedback from 16 additional model-sculpt sub-agents,
so several counts below cite that larger pool)  ·  **Span:** 2026-07-03 → 2026-07-20

## What's working (preserve these)

- **Pure-logic-first splits before touching DOM/Three.js/Worker code.** Landing
  grid packing, param-union, and part-tree logic as unit-tested pure modules
  before wiring UI let three different sessions (multi-part assembly view, part
  grouping, 3MF packing) prove correctness cheaply and kept the risky DOM work
  small. Keep defaulting to this split.
- **A throwaway Playwright screenshot spec is consistently the highest-signal
  verification step**, cited as decisive across assembly-view, tool-history
  auto-repair, and 3MF packing — it caught bugs (a pool that never resolved,
  edit tools acting on a hidden part, wrong dialog wiring) that typecheck/unit
  never could. The manual-verification doctrine in CLAUDE.md is earning its
  keep; don't weaken it.
- **`model:preview` as the inner loop for geometry** (blender-parity verbs,
  catalog refresh) and **the PLAYBOOK ratchet compounding across inverse-CAD
  sessions** (v2 → armor → Benchy, each converging faster on a new geometry
  class with zero part-specific babying) are both working exactly as designed —
  protect them.
- **Asking a scoping/design question before polishing** (assembly-view's
  read-only-vs-editable question; part-grouping's constraint-mapping pre-work)
  repeatedly collapsed multiple bug reports into one coherent model or made the
  design fall out with no rewrite.
- **`deform.md`'s explicit trap documentation** (e.g. "round first, label/paint
  after") was cited by 4 independent rework agents as the difference between a
  confident one-shot edit and trial-and-error — this batch adds three more
  documented traps (below) in the same style.
- **`work-reviewer`** caught real regressions the implementing agent's own e2e
  missed twice this batch (a collapsed-group drag no-op; a JSON-serialization
  diff blowup) — keep running it before marking PRs ready.

## Top friction (ranked)

1. **[tooling] No warm-browser loop for UI iteration** — 2 sessions this batch
   (multi-part assembly view, 3MF packing dialogs) independently asked for
   this, and the 3MF entry notes it's "the same wish as prior retros" — this
   is a chronic, high-cost gap. Every UI-iteration round pays a cold ~4s WASM
   boot + fresh session build inside Playwright; one session estimated ~5
   iterations cost minutes of dead wall-clock. The repo already has this
   pattern for models (`bin/partwright.mjs daemon start`); it doesn't exist for
   the full app UI. **Filed to backlog below — needs a new script, out of
   docs-only scope.**
2. **[tooling] `scatter` placement feedback** — 4 independent rework agents
   this batch (already tracked as #928's top item; this batch quadruples the
   vote). `count` is a request, not a guarantee, and the only feedback signal
   today is counting dots in a rendered PNG. Wants: a `placedCount` stat, a
   dry-run mode returning anchor points, a documented overshoot heuristic.
3. **[tooling] No orchestration/convergence driver for multi-agent inverse-CAD
   runs** — 3 sessions (v2, armor-genericity, Benchy) each independently hit
   orchestration bookkeeping gaps: a part silently never assigned an agent
   (caught only by a final manual sweep), a stale "best" left uninvalidated
   after a gate-code change, and no way to tell "agent still running" from
   "best/ exists" so an orchestrator doesn't consume a moving target. All three
   point at the same missing piece: a `status.mjs`-style driver with per-part
   state files, described but never built.
4. **[docs — applied this PR] Two ops-sizing traps hit 2–3 agents each**:
   sizing `scatter`'s `offset` against an instance's own half-thickness, and
   `round`/`smoothWeld` lattice-ing over an entire bbox to smooth one small
   seam. Both now have worked-example/recipe documentation in `deform.md` (see
   below) — the *first-class API convenience* versions (`seat:` option,
   `region:` option) remain backlog.
5. **[cost, n=1 but high] Tool-history repair has four separate implementations**
   (Anthropic/OpenAI/Gemini/UI-detector) that can disagree, which is why an
   "OpenAI 400" bug turned out to carry an Anthropic-shaped body from a
   proxying custom provider — already tracked as #914, still unresolved and
   still the kind of bug that costs multi-turn investigations.
6. **[docs — applied this PR] Three sharp, cheap-to-fix precision gaps**: the
   `Grep` tool has no binary-mode flag (one agent burned a turn discovering
   this — CLAUDE.md said "use grep -a" without saying *which* grep), a
   short-viewport rail is invisible to drag e2e tests, and the Worker
   init/ready handshake fails silently (hang, not rejection) when skipped.
   All three fixed in this PR (see below) — cheap, concrete, no more sessions
   should re-discover them.

## Changes applied in this PR

- `CLAUDE.md`: clarified the `main.ts` NUL-byte grep guidance — the dedicated
  `Grep` tool has no binary-mode flag; the fix is Bash `grep -an`/`rg -a`, not
  the `Grep` tool. Bumped "three independent sessions" → "four" (this batch's
  3MF-packing session re-hit it).
- `docs/playwright-guide.md`: added gotcha #6 — short scrollable rails (e.g.
  the parts list) clip drag targets out of view at the default viewport;
  bump to a taller viewport for rail/list-drag specs. (part-grouping)
- `docs/architecture-notes.md`: added a "Worker init/ready handshake" section
  documenting the `init`→`ready` protocol, the silent-hang failure mode when
  it's skipped, and the `error` message type new Worker clients must handle.
  (multi-part assembly view)
- `public/ai/deform.md`:
  - Added a worked numeric example for sizing `scatter`'s `offset` against an
    instance's own half-thickness (3 rework agents hit burial-by-guesswork).
  - Documented the **local-weld recipe** for `round`/`smoothWeld` — clip both
    parts to a tight box around the seam, weld the clip, union the
    remainders back in — so smoothing one seam no longer requires lattice-ing
    the whole model (2 rework agents).
  - Documented `round(mode: 'concave')` as the preferred retrofit tool for
    CSG-assembly seams (vs. `'both'`/`smoothWeld`, which erode acute swept
    corners at any radius) — a discovery from the catalog-refresh batch worth
    generalizing.

## Backlog (needs a human or the tooling/linter agent)

  WASM hot across `window.partwright` calls + screenshots, for UI features
  iterated in a tight loop. Raised again this batch; recurring across prior
  retros per the 3MF-packing entry.
- [ ] **`scatter` placement feedback** — `placedCount` return stat, a dry-run
  mode returning anchor points without building instances, and a documented
  overshoot heuristic for `count`. 4 votes this batch (tracked: #928).
- [ ] **Inverse-CAD convergence driver** — a `status.mjs`-style tracker with
  per-part state files: shows unassigned parts, flags a stale "best" after a

  the now-documented manual half-thickness math. 3 votes.
- [ ] **Single shared tool-history repair pass** applied before payload
  construction for all AI providers, so the UI's "is it broken?" detector and
  the actual send-path transform can never disagree (tracked: #914).
- [ ] **Provider-diagnostics field** recording which request builder/endpoint

- [ ] **`npm run bake -- <file> "<Name>" [tags]`** one-shot catalog-bake
