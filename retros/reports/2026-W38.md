## Top friction (ranked by cross-session frequency × cost)

1. **[tooling] No warm-browser loop for general UI iteration — 2 sessions.** The repo has a warm-browser daemon for *model* rendering (`bin/partwright.mjs daemon start`), but nothing analogous for UI features: the assembly-view and 3MF-packing sessions each paid a full cold WASM-boot + session-build inside every Playwright verification round (~30-40s × ~5 rounds each). The 3MF-packing entry explicitly flags this as a repeat wish. **Action: backlog** (needs a new harness, not a doc fix) — see below.
2. **[inverse-cad] The orchestration/state layer has no reliable tracking of agent completeness or result freshness — 3 sessions, different failure each time.** `inverse-cad-v2`: a stored "best" silently went stale after `gates.mjs`'s genus convention changed mid-run, caught only by a second agent's flag. `armor-genericity`: one part (`armor_shoulder`) was never assigned an agent at all — a bootstrap-converged sibling made the launch count look complete, caught only by a final manual sweep. `benchy-foreign-mesh`: a catalog bake consumed an agent's *interim* best while it was still polishing, because nothing distinguished "still running" from "best exists." Three different symptoms, one root cause: the pool-of-agents orchestration has no status/state file. **Action: backlog** (a `status.mjs` driver + a "finished" marker in `turn.mjs`'s output, per the entries' own proposals).
3. **[deform API] `scatter`/`round`/`smoothWeld` friction, already vote-counted by the source entry — largest single-topic cluster.** `scatter` placement is a request not a guarantee (4 agents want a `placedCount` stat / dry-run mode); `round`/`smoothWeld` operate over the whole input bbox rather than a local region (2 agents, one invented a manual clip-weld-restitch recipe); offset-vs-instance-thickness sizing was trial-and-error for 3 agents (asking for a worked example or a `seat: 'flush'|'proud'|'buried'` convenience); thin-feature radius ceilings are sharper than documented (3 agents — `deform.md` was already updated mid-batch with a caution, a numeric rule-of-thumb is still wanted). All of this is already tracked against issue **#928** per the source entry; nothing new to file, but the vote count roughly quadrupled this cycle. **Action: backlog** (feature/API additions, out of this skill's doc-only scope).
4. **[catalog/geometry] No single trustworthy component/genus counter for degenerate or foreign meshes — 2 sessions.** `multipart-kits-overview`: engine `decompose()`, the app's stats-computation count, and a welded-mesh census disagree on degenerate meshes (and `decompose()` flip-flops run to run) — each disagreement cost a ~2 min bake round-trip. `benchy-foreign-mesh`: mesh-χ genus went wildly negative on a self-touching internet mesh, forcing a mid-task `voxelGenus.mjs` build. Related to, but a level below, the already-documented `componentCount` vs `voxelPieceCount` distinction. **Action: backlog** (a "count it three ways and explain disagreements" tool).
5. **[docs, applied this PR] Two single-session findings were concrete and cheap enough to fix directly** even though each was raised once: (a) the `src/main.ts` NUL-byte callout told agents to "use `grep -a`" without saying the dedicated `Grep` tool has no such flag, costing a wasted call before falling back to `Bash`; (b) rail/list-drag Playwright specs silently miss on the default viewport because the parts list scrolls out of the clipped area below ~900px tall. Both are precise, low-risk clarifications to existing docs rather than new rules — applied below.
6. **[tooling, applied this PR] Worker-client handshake protocol had no written form.** The assembly-view pool implementation hung silently (no error, `Promise.all` never resolved) because a new pooled Worker client skipped the geometry Worker's `init`→`ready` handshake and didn't handle the `error` message type. One session, but the failure mode (silent hang, no static signal) is exactly the kind of trap worth writing down once. Added to `docs/architecture-notes.md`.
