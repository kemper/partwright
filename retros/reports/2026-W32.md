# Retro Report — 2026-W32

**Entries reviewed:** 12 (from 12 sessions, one of which — catalog-refresh-agent-feedback — aggregates 16 sub-agent retros, so ~27 agent-perspectives total)  ·  **Span:** 2026-07-06 → 2026-07-20

## What's working (preserve these)

- **`deform.md`'s explicit-trap documentation converts trial-and-error into a single confident edit.** The "round first, label/paint after" rule alone was cited by 4 independent catalog-refresh agents as the thing that saved them a debugging round. Keep writing traps down as soon as they're found, in the doc the next agent will actually read.
- **`scatter`'s `where(p, n)` predicate handles real exclusion geometry with no manual trig** — cap-only spots, spine-sparing scatter, sloped-only placement all fell out of sampling the real built surface, and it found a latent bug for free (a hand-computed spot ring that buried 9/10 spots).
- **The bake/render → look → adjust loop (`model:preview`, multi-angle `--view` tiling, native `sharp` crops) remains the highest-value verification step** across every model-shaped task this batch — it caught real defects (corduroy terracing, a knife-edge fin bug) that stats alone would not have.
- **Parallel `model-sculpt` subagents keep expensive render-iterate loops out of the orchestrating agent's context** — 5 showcase models and 16 catalog refreshes both used this pattern and it scaled cleanly.
- **The inverse-CAD PLAYBOOK ratchet keeps compounding.** Three separate sessions (v2, armor genericity, first foreign mesh) each transferred the prior era's recipe near-verbatim and converged new geometry classes in a handful of turns — "requiring PLAYBOOK candidates in every subagent's return format" is the mechanism, not luck.
- **Measure-the-instrument-first.** The inverse-CAD v2 session's single 5-line self-distance sanity check exposed a 0.15mm metric noise floor that had been silently invalidating "passing" results — the highest-leverage finding of that project, and worth defaulting to on any new numeric gate.
- **Pre-work exploration against the existing docs pays for itself repeatedly.** Both the part-grouping and mesh-to-code sessions cite mapping constraints (schema ladder, NUL-byte caveat, integration templates) against `CLAUDE.md`/docs *before* writing code as what made the design fall out immediately instead of being discovered mid-implementation.
- **Reading the existing tests before changing shared logic** (3MF packing session) proved backward-compat before the edit landed, rather than after a red CI run.

## Top friction (ranked)

1. **[deform / catalog] Sizing and scoping asks for the Blender-parity verbs — up to 4 agents per item.** The catalog-refresh batch (16 agents) converged on the same few gaps: `scatter`'s `count` is a request not a guarantee (4 agents — already tracked as #928, this batch quadruples the vote); `offset` sizing against instance thickness was trial-and-error (3 agents, two buried their instances on the first pass); `round`/`smoothWeld`'s documented radius ceiling is sharper than stated in practice (3 agents); `round`/`smoothWeld` lattice the whole input bbox even for a tiny seam (2 agents, one invented a manual clip-weld-stitch workaround).
   → **Applied:** `public/ai/deform.md` now has (a) a worked `offset`-vs-instance-thickness sizing recipe under Scatter, (b) a "radius ≈ 4–6% of edge length" machined-look rule of thumb under Round, and (c) the local-weld clip/weld/stitch recipe documented under smoothWeld as the workaround until a native region option exists.
   → **Backlog:** native `region`/bbox scope on `round`/`smoothWeld`; a `placedCount` stat + dry-run mode + documented overshoot heuristic for `scatter` (#928); a "fraction of label surface exposed" stat (1 agent, high value — would make the toadstool-style buried-paint class of bug gate-able headlessly); `api.placeOnFace(shape, {face})`; a genus-change flag in `model:preview` output.

2. **[inverse-cad tooling] No orchestration/status layer across the multi-agent convergence pipeline — 3 sessions independently hit this.** v2 had a "passing" stored best silently go stale when `gates.mjs` was fixed mid-run (caught only by a mirror-twin agent, not tooling). Armor-genericity had a part (`armor_shoulder`) silently never get an agent assigned — a bootstrap-converged sibling made the launch count look complete, caught only by a final manual sweep. The foreign-mesh (Benchy) session baked from an agent's still-polishing interim best because there's no signal distinguishing "finished" from "best exists." All three sessions independently proposed the same fix: a driver/status script.
   → **Backlog:** build `scripts/inverse-cad/status.mjs` — a convergence driver that tracks per-part agent assignment, run state (in-progress / finished / best-exists-unverified), and stamps the gates-code version into each stored best so a later gate fix flags stale passes instead of silently keeping them. Related, lower-cost items from the same cluster: formalize `voxelGenus.mjs` (built ad hoc this batch for dirty/self-touching meshes) as a supported gate tool; default subagent workspaces to something durable (or require an explicit end-of-run commit step) so an ephemeral container loss can't erase converged candidates that currently live only in gitignored `.plans/`.

3. **[tooling] Cold Playwright boot is the biggest lever for iterating on a UI feature — raised again this batch, explicitly called "the same wish as prior retros."** Both the multi-part-assembly-view session (~5 iteration rounds, each paying WASM boot + session build + pool wait) and the 3MF-packing session flagged this independently. Note this is distinct from the model-rendering daemon that already exists (`bin/partwright.mjs daemon start` / `partwright call <method>`, documented in `docs/headless-cli.md`) — that daemon gives fast repeat access to the `window.partwright` method surface and real model renders, but neither session's pain was a model render; it was verifying DOM/UI state (popovers, hidden-attribute toggles, drag targets) that isn't reachable through a `window.partwright` call.
   → **Backlog:** extend the Phase-2 daemon (or a sibling command) to support full-page DOM screenshots and basic interaction (click/type) against the warm browser session, not just `window.partwright` method calls — so a UI-feature iteration loop can skip Playwright's per-run cold boot the way model iteration already does.

4. **[export/packing] No visual verification tool for a packed build-plate layout — 2 sessions, same feature area, different PRs.** Both the Bambu plate-layout session (#904) and the follow-on packing-strategy session (#910) independently wanted to *see* the packed arrangement instead of parsing `<item>` transforms out of exported XML and asserting bed-bounds numerically.
   → **Backlog:** a headless build-plate rasterizer — parts as footprint rects on the bed, rendered to PNG — the packing equivalent of `model:preview`.

5. **[AI providers] Tool-history repair logic is duplicated across all four providers (#914, already filed).** One session burned several turns locating which of four separate implementations (Anthropic, OpenAI, Gemini→shared, UI-detector→shared) produced a given 400, and separately hit an "OpenAI 400" that actually carried an Anthropic-shaped body (an OpenAI-compatible endpoint proxying to Claude).
   → **Backlog (already tracked, no new filing needed):** unify the repair pass across all four provider builders behind the one shared function Gemini already uses; add a provider-tagged diagnostics field recording which request builder/endpoint actually produced a 4xx.

6. **[catalog baking] No canonical "restart dev server, then bake" helper.** One session hit stale/dead dev-server bakes twice, plus a `pkill -f vite` that self-matched the invoking shell's own cmdline.
   → **Backlog:** a one-shot `npm run bake -- <example.js> "<Name>" [tags]` that owns the dev-server lifecycle end to end (start-if-needed, wait, bake, update both manifests in canonical serialization, regenerate the dev thumbnail) — precisely scoped in the source entry.
