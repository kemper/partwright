# Retro Report — 2026-W32

**Entries reviewed:** 12 files (one — `2026-07-20-catalog-refresh-agent-feedback.md` — is itself an aggregate of 16 model-sculpt sub-agent retros from PR #929, so the effective sample is ~27 distinct sessions) · **Span:** 2026-07-03 → 2026-07-20

Two clear clusters this batch: a run of five **inverse-CAD convergence** sessions (framework v2, armor genericity, foreign-mesh/Benchy, plus two multi-part-kit/reconstruction sessions) and a run of **UI feature** sessions (assembly grid view, tool-history repair, Blender-parity verbs + catalog refresh, part grouping, two 3MF packing PRs).

## What's working (preserve these)

- **Pure-module-first splits with node unit coverage before touching DOM/Three.js** — the assembly-grid view (`layout.ts`/`sharedParams.ts`) and part-grouping (`partTree.ts`) sessions both credit this for letting the trickiest logic land fully verified before any browser round-trip, and for surviving a rework untouched.
- **Spec-driven Playwright screenshot as the single highest-value verification step** — independently named as decisive by the assembly-view and both 3MF-packing sessions ("is it wired right?" a typecheck can't answer).
- **The inverse-CAD PLAYBOOK ratchet — merge each returned agent's tactics before launching the next wave** — three separate sessions (v2, armor genericity, Benchy) confirm this is what turned dozens of independent part-convergence agents into one compounding system; the armor phase went 13-for-13 with agents reporting "no new tactics needed" once the recipe matured.
- **`deform.md`'s explicit trap documentation** ("round first, label/paint after") was cited by four independent catalog-refresh agents as the difference between a confident single edit and trial-and-error.
- **`work-reviewer` catching regressions the author's own e2e missed** — named again this batch (part-grouping's collapsed-group drag bug, Blender-parity's manifest-diff bug), consistent with every prior report.
- **Delegating expensive iterate loops to disposable subagents** (model-sculpt for catalog renders, inverse-sculpt for part convergence) keeps hundreds of tool calls and preview images out of the driving session's context — reconfirmed across both clusters this batch.

## Top friction (ranked by cross-session frequency × cost)

1. **[tooling] No warm-browser loop for general UI iteration** — 2 sessions (assembly-view, 3mf-packing-strategy), and the second explicitly flags it as "same wish as prior retros." Every UI-feature round pays a cold ~4s WASM boot + session build inside a fresh Playwright process; a persistent warm-editor daemon (analogous to the model-preview render daemon that already exists) is the standing highest-leverage ask for this class of work. **No repo-side doc fix applies** — filed to backlog as it needs new tooling.
2. **[process] Inverse-CAD multi-agent orchestration has no driver/status layer** — 3 sessions (v2, armor-genericity, Benchy). Concretely: a part silently never got assigned an agent and was only caught by a final manual sweep; the stop-hook fired ~20 times during long agent waits with nothing to reconcile; there's no convention distinguishing "agent finished" from "a `best/` exists but is still being refined" (one session baked a catalog entry from a moving, unfinished `best/`). Backlog — needs a `status.mjs`-style driver and a hook/tooling change, both out of this skill's direct-edit scope.
3. **[docs, fixed this PR] `main.ts` NUL-byte guidance was incomplete.** CLAUDE.md told agents to use `grep -a`/`rg -a` on `main.ts`, but didn't say the dedicated `Grep` tool doesn't accept `-a` at all — one session burned a call finding that out the hard way before falling back to Bash. **Action:** clarified in CLAUDE.md.
4. **[testing, fixed this PR] Rail/list-drag e2e silently miss off-screen rows at the default viewport.** The part-grouping session lost two runs to a drag target scrolled out of the parts-list clip box before discovering a 1400px viewport was needed. **Action:** added to `docs/playwright-guide.md`'s AI-agent-gotchas list.
5. **[worker pattern, fixed this PR] New pooled-worker clients re-derive the init/ready/error handshake by hanging first.** The assembly-view session's build pool silently hung (no thrown error) until a debug log revealed the missing `{type:'init'}` → `ready` handshake. **Action:** new "Worker init/ready/error handshake" section in `docs/architecture-notes.md`, since the fact pattern was precise and already verified by the shipping PR.
6. **[catalog tooling] No one-shot bake helper; `pkill -f vite` self-matches the invoking shell.** One session lost two confusing exit-144s to `pkill -f vite` matching its own shell's command line, and wants a single `npm run bake -- <file> "<Name>"` that owns the dev-server lifecycle instead of the current 4-step manual dance. Single session this batch, but concrete and cheap to build — backlog (new npm script).
7. **[AI] Tool-history repair logic is duplicated across all 4 provider builders**, so the UI's "is it broken?" detector and the actual send-path transform can silently disagree — already tracked as **#914** from the session that filed it; this batch adds a second, related ask (a provider-tagged diagnostic recording which builder/endpoint actually 400'd) as a **#914** addendum rather than a new issue.
8. **[model authoring] `public/ai/deform.md` still lacks two asks from the 16-agent catalog-refresh batch**: a worked numeric example for sizing `scatter`'s `offset` against instance thickness (3 agents needed it), and a "radius ≈ 4–6% of edge length" rule of thumb for `round`/`smoothWeld` (3 agents hit sharper-than-documented thin-feature limits). `public/ai/*.md` is outside this skill's direct-edit scope (`CLAUDE.md`/`docs/*`/`.claude/skills/*` only) — flagged to backlog for whoever owns that doc next.
9. **[tooling] Component/topology counters disagree with each other on degenerate meshes** — engine `decompose()`, the app's stats computation, and a welded-mesh census gave three different answers (and `decompose()` itself flip-flopped run to run), costing ~8 bake round-trips to debug in one session. One vote this batch; backlog (a headless "count it three ways and explain the disagreement" tool).

## A tension worth naming

The inverse-CAD cluster's "Longed for" items (driver script, gates version-stamping, durable workspaces) are all **orchestration/process gaps around a framework that is otherwise working extremely well** (37/37 parts converged, sub-0.01mm mean chamfer). Don't read this report as "the inverse-CAD tooling needs rework" — it's "the tooling has outgrown running it by hand across ~20 concurrent agents," which is a scaling problem, not a correctness one.
