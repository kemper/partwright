## Top friction (ranked)

1. **[process] Inverse-CAD multi-agent orchestration has no driver** — 3 sessions (`20260703-inverse-cad-v2.md`, `20260704-inverse-cad-armor-genericity.md`, `20260705-benchy-foreign-mesh.md`). Symptoms ranged from a part silently never getting assigned an agent (caught only by a final manual sweep) to consuming a subagent's still-polishing interim `best/` because there was no "finished" signal. Root cause: manual pool management across up to ~20 parallel launches, with no status table, auto-refill, or completion detection. **Action:** filed as a backlog tooling item (a `status.mjs` driver was in the original design and never built) — this is new tooling, not a doc fix.
2. **[tooling] No single trustworthy component/topology counter** — 2 sessions (`20260705-benchy-foreign-mesh.md`, `20260705-multipart-kits-overview.md`). `Manifold.decompose()`, the app's `statsComputation` count, and mesh-vs-solid genus disagree (and even flip-flop run-to-run) on degenerate/self-touching meshes; one session had to hand-build `voxelGenus.mjs` mid-task to get a usable genus reference. **Action:** backlog — productionize a "count it all ways and explain disagreements" tool.
3. **[process] Warm-browser loop for UI iteration** — 2 sessions (`2026-07-06-multi-part-assembly-view.md`, `20260707-3mf-packing-strategy.md`) independently wanted the UI/editor equivalent of the model-render daemon that already exists for headless geometry (`bin/partwright.mjs daemon start`): each cold Playwright-driven screenshot round pays ~30-40s of WASM boot + session build. **Action:** backlog — this needs new tooling, not a doc change.
4. **[docs] `deform.md` gaps with corroborated multi-agent votes** — from the 16-agent catalog-refresh batch: scatter's `offset` sizing (3 agents, two fully buried their instances on a first guess) and round's aesthetic-radius default (3 agents) were trial-and-error without a worked number. **Action applied this PR** — added a worked `offset ≈ -0.5·t` relationship and a "radius ≈ 4–6% of edge length" rule of thumb to `public/ai/deform.md` (see below). The higher-cost asks from the same batch — a `placedCount`/dry-run mode for `scatter`, and a `region`-scoped option for `smoothWeld`/`round` — require API changes, not doc edits, and are left on the backlog (already tracked as top items in issue #928).
5. **[docs] Two single-session but low-cost, high-confidence clarifications applied directly**: (a) the `main.ts` NUL-byte section didn't say the dedicated `Grep` tool has no `-a` flag, so an agent burned a call discovering that only `Bash`-invoked `grep -a`/`rg -a` works; (b) a new Worker-backed pool client hung silently on `Promise.all` because the geometry Worker's `init`→`ready` handshake and `error`-message contract weren't written down anywhere. Both are factual/protocol clarifications (not new process rules) in files whose whole purpose is exactly this kind of gotcha, so they were applied despite being single-session.

## Changes applied in this PR

- `CLAUDE.md`: clarified the `main.ts` NUL-byte-zone note — the dedicated `Grep` tool has no `-a` equivalent; use `Bash`'s `grep -a`/`rg -a` directly. (Cited: `20260707-3mf-packing-strategy.md`.)
- `docs/playwright-guide.md`: added gotcha #6 — rail/list drag e2e specs need a taller-than-default viewport, or rows scrolled out of the clip rect are silently missed. (Cited: `20260706-part-grouping.md`.)
- `docs/architecture-notes.md`: added a "Worker init/ready/error handshake" section documenting the geometry Worker's `init`→`ready` contract and the `error` message type, for anyone adding a new Worker pool/client. (Cited: `2026-07-06-multi-part-assembly-view.md`.)
- `public/ai/deform.md`: added a worked `offset ≈ -0.5 · t` sizing relationship to the Scatter section, and a "radius ≈ 4–6% of edge length" aesthetic-default rule of thumb to the Round section. (Cited: `2026-07-20-catalog-refresh-agent-feedback.md`, 3 agents each.)
