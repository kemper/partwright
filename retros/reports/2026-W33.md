## What's working (preserve these)

- **The spec-driven Playwright screenshot loop is still the highest-signal verification step**, confirmed independently again (assembly grid, 3MF packing dialogs, tool-history repair). It caught bugs typecheck/unit never could — a Worker pool silently never resolving, edit tools acting on a hidden part.
- **`model:preview` inner loop + parallel `model-sculpt` subagents scale cleanly**: 5 showcase catalog models iterated up to 65 tool calls each entirely out of the main context and all shipped print-valid; a defect (corduroy terracing) was caught purely by *looking* at a render, exactly as the visual-verification doctrine predicts.
- **Explicit trap documentation in `deform.md` pays for itself repeatedly** — the "round first, label/paint after" rule was independently cited by 4 of 16 catalog-refresh agents as the difference between a confident one-line fix and trial-and-error. This is direct evidence the doc-a-Gotcha pattern works and is worth continuing.
- **Pure-module-first splits keep hard logic unit-tested before any DOM/Three.js touches it** (assembly grid's `layout.ts`/`sharedParams.ts`, part-grouping's `partTree.ts`) — both sessions reported this as the reason their trickiest logic never regressed through a multi-round rework.
- **The inverse-CAD PLAYBOOK ratchet is compounding exactly as designed across three consecutive phases** (v2 → armor genericity → foreign-mesh/Benchy): per-part turn counts fell from a median of several to one, and the armor phase's recipe transferred to Benchy — a never-seen 225k-tri internet mesh — with zero part-specific babying. "Measure the instrument first" (the 0.15mm v1 metric noise-floor bug) remains the single highest-leverage finding across the whole inverse-CAD effort.
- **`scatter`'s `where(p, n)` predicate handles real placement-exclusion cases with no manual trig**, and sampling the real built surface fixed a latent bug for free in one case (buried spot ring).

## Top friction (ranked)

1. **[docs] `deform.md` gaps in `scatter`/`round`/`smoothWeld` sizing guidance — converging asks from up to 4 independent agents per item (16-agent aggregate batch)**
   Root cause: no worked example for sizing `scatter`'s `offset` against instance thickness (2 first passes fully buried their instances), no radius rule-of-thumb for `round`, and no documented workaround for welding a small feature onto a large body (2 agents independently invented the same clip-weld-restitch recipe).
   → **Applied:** `public/ai/deform.md` — added an `offset`-sizing worked example, a 4–6%-of-edge-length starting radius for `round` (plus the `mode:'concave'` retrofit note), and the region-clip local-weld recipe for `smoothWeld`/`round`.

2. **[dev workflow] No warm-browser/dev-server loop for UI iteration — recurring across sessions**
   Root cause: every UI-feature verification round pays a full cold Playwright boot (WASM init + session build + ~12s pool-build in one case) even though the repo already has a warm-daemon pattern for model rendering (`bin/partwright.mjs daemon`). Two sessions this batch hit it explicitly, one calling it "same wish as prior retros" — this is now a repeatedly-longed-for gap distinct from the model-preview daemon, which only solves headless *model* iteration, not UI.
   → **Backlog** (see below) — this needs new tooling, not a doc change.

3. **[testing] Fixed `waitForTimeout` / no readiness-poll helper causes flaky e2e shards**
   Root cause: at least two open flaky-test issues (#911, #912) trace to fixed-timeout/modal-race patterns; this batch's 3MF-packing session named the same root cause independently.
   → **Backlog** — already tracked as #911/#912; the ask that isn't yet filed is a shared `waitForEngineReady`-style helper/lint so the whole class doesn't get re-derived per spec.

4. **[worker infra] No documented Worker-client init/ready/error handshake — silent-hang class of bug**
   Root cause: `buildInPool` (assembly grid's Worker pool) hung with no error until a debug `console.warn` was added; the geometry Worker's contract (must `init`→`ready` before `execute`, must handle the `error` message type) exists only as tribal knowledge in `engineWorker.ts`.
   → **Applied:** `docs/architecture-notes.md` — new "New Worker-client checklist" section documenting the handshake and the two most common silent-failure modes.

5. **[testing] Rail/list-drag e2e tests silently miss scrolled-out rows at the default viewport**
   Root cause: the parts-list rail is a short scroll box at 1280×900; drag-by-absolute-position tests targeting scrolled-out rows no-op instead of failing loudly. One session burned two runs before discovering this and fixing it locally in `tests/part-grouping.spec.ts` with a 1400px-tall viewport in `beforeEach`.
   → **Applied:** `docs/playwright-guide.md` — added as gotcha #6, pointing at the working pattern already in that spec.

6. **[main.ts] Module-scope vs. `main()`-setup-scope boundary is undocumented and cost a rewrite**
   Root cause: a new helper (`openAssembly`) was written at module scope, but the helpers it needed to call (`selectPart` and every tool-close callback) turned out to be nested inside `async function main()`. The fix pattern (module-scope `let`, assigned from inside `main()`) already exists in the codebase (`applyAssemblyChrome`) but wasn't written down anywhere.
   → **Applied:** `docs/architecture-notes.md` — new section describing the split and the `let`-assigned-in-`main()` pattern.

7. **[inverse-cad tooling] Orchestration bookkeeping doesn't scale past ~10 concurrent part-convergence agents — recurring across 3 sessions**
   Root cause: no driver/status table for the ~20-agent convergence pools. Concretely this cost: a part silently never got an agent assigned (caught only by a final manual sweep), a stale "passing" `best` after a gates.mjs fix went undetected until a sibling agent flagged it, and a catalog was baked from an agent's still-polishing interim result because there's no "agent finished" vs. "best exists" signal.
   → **Backlog** — needs a real driver script (`status.mjs`) plus two small protocol additions (gates-code-version stamp on `best`/`metrics`, a completion marker distinct from "a best exists"). This is inverse-cad-specific tooling, not doc-fixable.

8. **[multi-part tooling] No single trustworthy component counter**
   Root cause: engine `decompose()`, the app's stats-computation count, and a welded-mesh census disagree on degenerate meshes, and `decompose()` itself is non-deterministic run-to-run near the disagreement boundary. Each probe round-trip through the bake page costs ~2 minutes; this echoes the `componentCount` confusion theme flagged as systemic back in the W24 report (item #4), but that fix (decompose-and-inspect discipline, `model:preview --explain-components`) doesn't cover the *voxel-vs-mesh* disagreement raised here.
   → **Backlog** — a headless "count it all three ways and explain disagreements" tool, as proposed by the session.
