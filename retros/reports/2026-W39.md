## Top friction (ranked by cross-session frequency × cost)

1. **[tooling, no direct fix here] No warm-browser loop for *UI* iteration** — 2 sessions this batch (multi-part-assembly, 3mf-packing-strategy), and the latter explicitly flags it as "the same wish as prior retros." It has never actually been written into a backlog item despite recurring across cycles — filed below as a first-class backlog item now that it's been named as a repeat offender.
2. **[export/packing] No way to visually verify a packed build-plate layout** — 2 same-day sessions (3mf-packing-strategy PR #910, bambu-plate-layout-packing PR #904) both had to verify plate packing by parsing XML `<item>` transforms and asserting bed bounds numerically, with no way to *see* the arrangement the way `model:preview` shows geometry.
3. **[docs, fixed this PR] The NUL-byte `main.ts` trap keeps costing turns even though it's documented** — a 4th session hit it, this time burning a wasted `Grep -a` attempt (the dedicated `Grep` tool silently has no `-a` flag) before falling back to `Bash grep -an`. **Action:** added a bullet naming the `Grep`-tool gap explicitly and bumped the session count.
4. **[docs, fixed this PR] Worker init/ready/error handshake had no written pattern** — multi-part-assembly's pool silently hung (`Promise.all` never resolved, no error) until a debug `console.warn` revealed a missing `{type:'init'}`→`ready` handshake and an unhandled standalone `error` message type. **Action:** added a "New Worker clients" section to `docs/architecture-notes.md`.
5. **[figures/tooling] `scatter` placement feedback is undershooting/overshooting with no signal but counting dots in a PNG** — already tracked as `#928`; this batch's 16-agent catalog-refresh feedback independently quadruples the vote (4 of 16 rework agents hit it). Bumping its backlog priority.
6. **[multi-part] No single trustworthy component/part counter** — engine `decompose()`, the app's stats count, and welded-mesh census disagree on degenerate meshes and `decompose()` itself flip-flops run to run (multipart-kits-overview); each probe round-trip through the bake page cost ~2 min. New backlog item.
7. **[testing] Fixed `waitForTimeout`/modal-race patterns are the root of recurring flaky shard failures** — 3mf-packing-strategy traces two open flakes (`#911`, `#912`) to this pattern and asks for a repo-wide `waitForEngineReady(page)`-style readiness-poll helper instead of fixed waits.
8. **[inverse-cad] Orchestration/liveness bookkeeping is the one part of the framework that doesn't scale itself** — 3 sessions in this specialized subsystem (v2, armor-genericity, benchy-foreign-mesh) each hit a variant of "no driver to know what's in flight / whether `best/` is still moving": a silently-unassigned part caught only by a final sweep table, and an interim `best/` consumed mid-polish because there's no "agent finished" marker. This is `scripts/inverse-cad/`-specific tooling (a `status.mjs` driver was designed but never built) rather than a general CLAUDE.md process fix — noted as backlog for that subsystem's own maintainers.
