## What's working (preserve these)

- **Pure-module-first, DOM/Three.js last.** Landing the trickiest logic (grid packing, param union, `partTree.ts`, the inverse-CAD kernel) as dependency-free modules with fast vitest coverage before touching the UI kept several features regression-free through their whole rework (assembly-view, part-grouping, mesh-to-code-in-app, 3mf-packing-strategy all cite this independently).
- **`model:preview` / spec-driven screenshots as the inner loop.** Every geometry or UI change that got verified by *looking* (a throwaway Playwright spec, a `model:preview` render) caught bugs typecheck/unit couldn't — the corduroy-terracing defect, the pool-never-resolving bug, the hidden-part-edit bug. This is the doctrine paying for itself repeatedly.
- **`work-reviewer` catching real regressions** before they shipped (collapsed-group drag no-op, a 1300-line manifest diff from mismatched `json.dump` formatting).
- **The inverse-CAD PLAYBOOK ratchet.** Requiring subagents to return "PLAYBOOK candidates" turned 20+ independent convergence agents into one accumulating system — recipes matured and then transferred verbatim to new geometry classes (armor → foreign mesh), with agents reporting "textbook confirmation, no new tactics needed."
- **CLAUDE.md's existing pre-work constraints (schema ladder, `main.ts` scope split, NUL-byte caveat) doing their job.** The part-grouping session designed correctly on the first pass specifically *because* those constraints were already written down — the meta-signal that this file is being read and used, not just maintained.
- **Parallel model-sculpt subagents for independent visual-iteration work** — five showcase catalog models converged concurrently, out of the main context, all print-valid.

## Top friction (ranked)

1. **[tooling] No warm browser/dev-server loop for UI iteration** — 2 sessions explicitly (assembly-view, 3mf-packing-strategy — the latter calling it "same wish as prior retros," so this is at least a 3rd occurrence across weeks). Every verification round pays a cold ~4s WASM boot + fresh session build inside a new Playwright process; a 5-round UI feature burns minutes of dead wall-clock. The repo already has this pattern for model rendering (the render daemon / `partwright iterate`) but not for general UI. **Backlog** — highest-leverage ask this batch, still unbuilt.
2. **[docs] `api.scatter`/`smoothWeld`/`round` under-documented failure modes** — up to 4 independent agents per item within the catalog-refresh batch (scatter placement guarantees, offset-vs-thickness sizing, thin-feature radius limits, whole-bbox lattice cost). Doc-fixable parts applied this batch (see below); the API-shape asks (`placedCount`, dry-run, `region` scoping) need real feature work — already tracked as backlog (#928 for scatter placement, quadrupled by this batch).
3. **[process] Orchestration bookkeeping for large subagent pools** — 2 inverse-CAD sessions (armor-genericity, benchy) independently wanted a status/driver script: a part silently never got an agent assigned (caught only by a final manual sweep), and a "finished vs. best-exists" marker so an orchestrator doesn't consume a still-polishing agent's interim output. **Backlog.**
4. **[tooling] No single trustworthy component/part counter** — `Manifold.decompose()`, `statsComputation`, and the welded-mesh census disagree on degenerate meshes and flip-flop run to run (multipart-kits-overview). CLAUDE.md already documents the `componentCount`-is-unreliable / `voxelPieceCount`-for-voxels workaround from a prior retro; the further ask (a headless "count it three ways and explain disagreements" tool, a `--verify-entry` post-import check) is new tooling. **Backlog.**
5. **[one-off, but cheap to fix] Two doc-precision gaps** — the `main.ts` NUL-byte note pointed at "`grep -a`/`rg -a`" without saying the harness's own Grep tool doesn't support `-a` (cost one wasted attempt before falling back to Bash), and the playwright guide had no note that rail/list drag e2e specs need a taller-than-default viewport (cost two runs + a debug scratch to discover rows were scrolled out of the clip). Both fixed this batch — see below.

## Changes applied in this PR

- `public/ai/deform.md`:
  - **Scatter** — added a worked numeric example for sizing `offset` against an instance's own half-thickness/height (the exact mis-sizing that fully buried two agents' first-pass instances).
  - **Round** — added a "radius ≈ 4–6% of edge length" starting-default rule of thumb (independent of the existing thin-feature ceiling), and documented `mode: 'concave'` as the retrofit tool for CSG-assembly seams (more robust than `mode: 'both'`/`smoothWeld` on acute swept corners) — a technique discovered mid-batch that wasn't written down anywhere.
  - **smoothWeld** — documented the manual "local weld" recipe (clip both parts to a tight box around the seam, weld the small pair, union the remainders back on) as the workaround until a first-class `region`/bbox scoping option exists, since both `round` and `smoothWeld` currently lattice over the whole input bbox regardless of how local the seam is.
- `CLAUDE.md`: clarified the `main.ts` NUL-byte search guidance — `grep -a`/`rg -a` is a Bash-only workaround; the Grep tool's wrapper has no `-a` flag and silently no-ops it.
- `docs/playwright-guide.md`: added a gotcha (#6) that rail/list drag specs need a taller-than-default viewport (~1400px) since short scroll boxes clip rows out of the hit-test area at the standard 1280×900.

- [ ] A headless build-plate-arrangement rasterizer (parts-as-footprint-rects → PNG) — the packing equivalent of `model:preview`, so plate-layout bugs are glanceable instead of only verifiable via XML-transform assertions.
- [ ] `api.placeOnFace(shape, { face })` — flat 2D relief placement onto one face of a box, to replace hand-derived per-face rotation matrices.
- [ ] A `genus`-change flag in `model:preview` output when iterating on one model in place (a fin-weld stitch silently went genus 0→10 — watertight and printable, but only caught by manual diffing).
