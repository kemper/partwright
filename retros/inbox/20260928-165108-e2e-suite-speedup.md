## Liked / Worked
- Per-test durations from the CI job logs (the `list` reporter prints each
  test's time) were enough to find the real problem in one pass. Simulating
  shard strategies offline before touching CI got it right first try
  (predicted 4.5 min/shard, measured 3.2–4.7).
- `tests/insert-codegen.spec.ts` (184 pure tests in 0.1s in the Node runner)
  was a ready-made proof that most of the suite's cost is per-test page boot.
- Fanning out 4 implementer agents in worktrees, all reusing one dev server
  I started, worked well because none of them touched `src/`.

## Lacked
- Nothing recorded per-test or per-file e2e timings over time, so a 2x shard
  imbalance (Playwright `--shard` balances by test COUNT) went unnoticed while
  the suite grew. (#971 now uploads JSON reports from the staging gate.)
- Agent worktrees live under `.claude/worktrees/` inside the repo root, which
  the Vite dev server watches. Their `npm ci` and file edits likely triggered
  full-page reloads, which showed up as "Execution context was destroyed"
  blips in shared-page tests. That cost a couple of agent re-runs.

## Learned
- What a fresh `page.goto('/editor')` resets that the API equivalents don't:
  `createSession()` keeps live paint regions and the active engine language;
  a plain `run()` re-resolves existing paint rather than clearing it; the
  editor buffer isn't restored to starter code; the replicad Worker's
  `lastShape` is never cleared. Now documented in `tests/helpers/sharedPage.ts`.
- Polling `partwright.changePart()` while a "Save all" is in flight races the
  app's own background save loop. Read `listVersions` from `db.ts` instead.
- Node 22's native fetch/Response/ReadableStream are enough for the AI provider
  request-builder tests. IndexedDB (`chatLoop.runTurn`) is the real bar for
  staying in Playwright.

## Longed for
- A scheduled job that refreshes `tests/e2e-timings.json` from the latest green
  staging-gate artifacts and opens a PR, so shard balance never drifts.
- Tell the Vite dev server not to watch `.claude/worktrees/**`
  (`server.watch.ignored`), so parallel agent worktrees can't reload pages in a
  shared dev server.
- A `fake-indexeddb` vitest setup, so `chatLoop`-driven tests (ai-autoresume,
  ai-transient-retry) could leave the browser tier too.
