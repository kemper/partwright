## Liked / Worked
- #1125's split between "gated = may run" and "trimmed = what's sent" (customContext.ts) made on-demand tool groups a filter on top of it, with no permission changes. Reusing it kept the diff small.
- The work-reviewer subagent caught the one real bug: Gemini rejects calls to undeclared tools (MALFORMED_FUNCTION_CALL), so "just call it, it still runs" was false there. My Gemini fetch stub happily returned the undeclared call. A stub only shows what the stub allows.

## Lacked
- No number for "how big is the AI's starting context" existed anywhere. It regrew from the May split (#355) to ~111K tokens, and the only signal was a user's outside review. Measuring needed a throwaway vite-node script. `npm run ai:budget` and the budget test now fill that gap.

## Learned
- The provider cache order on Anthropic is tools → system → messages, and the only tool breakpoint is the last tool, so ANY tool-list change is a full prefix re-write at the cache-write rate, not a tools-only miss. Now in docs/ai-internals.md.
- Plan mode already sends history containing tool_use for tools absent from `tools`, and every provider accepts that. Producing such a call is what fails (Gemini), not replaying one.

## Longed for
- A behavioural A/B harness for the in-app agent: N fixed prompts × {full tools, groups} against a real provider, reporting tool-error rate, round-trips, loadTools usage and a judge score. Unit/e2e tests prove the plumbing, not whether models actually reach for loadTools. Tracked on #1175.
- e2e stubs that mimic provider strictness: a Gemini stub that answers MALFORMED_FUNCTION_CALL when the response names a function missing from the request's declarations would have caught the bug in the spec itself.
