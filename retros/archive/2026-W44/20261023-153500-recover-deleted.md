## Liked / Worked
- The existing drag-reorder e2e (`parts.spec.ts`) caught a real layout
  regression: a pinned rail footer shrank the Objects list to ~24px on a
  720px-tall window. Without it the footer would have shipped.
- Part deletion being a code line (`api.removePart`) made part-undelete a pure
  string op + re-run — no storage at all, unit-testable in vitest.

## Lacked
- `playwright.config.ts` only looked for `/opt/pw-browsers/chromium-N/chrome-linux/chrome`;
  this sandbox image ships `chrome-linux64/`, so every e2e run failed to launch
  until patched (fixed in the PR). (cost: ~2 turns)
- `git stash` to get a main baseline also stashed that config fix, giving a
  false "fails on main too" signal — use `git stash push -- <paths>`.

## Learned
- The Objects rail lives in the left sidebar under the nav on desktop and can
  be only a few dozen px tall; anything `shrink-0` added to the rail steals
  directly from the list. Put new affordances inside the scrolling list.
- Each Playwright run wipes `test-results/`, so screenshots for
  `pr:screenshots` must come from the LAST run — regenerate them together.

## Longed for
- `npm run pr:screenshots -- --spec <grep>` that runs the spec(s) and uploads
  the PNGs they wrote in one step, so an intervening test run can't delete them.
