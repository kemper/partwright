## Liked / Worked
- Driving the real panel on the user's 460k-tri STL with real mouse events
  found 5 bugs the API-level e2e never would have:
  - the auto flag was dropped, so every pin got a name tag;
  - hover rebuilt the action bar and wiped typed input;
  - Esc closed the whole tool panel;
  - the footer went off-screen;
  - an auto pin outranked a placed pin.
- The work-reviewer found 3 real blockers (duplicate pins under a lock, a
  fixed-region pin starving its part, empty parts from pins on unassigned
  triangles). It verified each with a throwaway vitest probe, which made
  the fixes quick to confirm.

## Lacked
- Playwright wipes `test-results/` on every run, so screenshots I meant to
  send the user disappeared when I ran the real spec afterwards. I had to
  regenerate them. (cost: ~2 turns)
- `getPartDraft()` caps the part list at `maxListedParts` (80). My scratch
  check for a new part at index ~89 silently failed, and it looked like a
  feature bug for 3 runs. (cost: ~3 runs)

## Learned
- `createToolPanelShell` closes on Escape via a bubbling document listener.
  A panel that wants Esc to clear its own state first must listen in the
  capture phase and stopPropagation only when it consumed the key.
- The shell's `max-h-[calc(100%-3.5rem)]` is relative to the container, not
  the docked top, so tall panels push their footer off-screen. Fit from
  `getBoundingClientRect().top`.

## Longed for
- A screenshot output directory for scratch specs that Playwright doesn't
  clean (e.g. `SCREENSHOT_DIR` defaulting to the session scratchpad).
- A `getPartDraft({ all: true })` (or a `partNames()` helper) so tests and
  agents can see every part without fighting the summary cap.
- A fix to `createToolPanelShell` itself: fit-to-window from the docked top,
  and an `onEscape` hook so panels can claim Esc without capture-phase
  tricks.
