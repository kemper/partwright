## Key decisions

**Parts own their pins, but the partition stays the source of truth.**
Every part always has at least one pin: an automatic one per region,
otherwise the user's or AI's. Rename and merge carry pins along, and renaming
to a taken name merges. I pushed back on one point: re-growing the whole model
from automatic pins does not reproduce the boundaries auto patches found. So
pin edits re-grow only the edited part and its neighbours, and whole-model
re-detection stays explicit. Hand fixes (`reassign`, the Fix brush) are fixed
triangles kept out of re-grows. My first version seeded growth from them, and
a unit test showed that leaks into the neighbour.

**Placed pins outrank automatic ones.** On the figurine, a pin clicked near a
part's automatic pin tied on the same triangle, and the new part got
nothing. Placed pins now go first and win shared triangles.

**Colours are assigned by neighbours, not by palette index.** I use 36
golden-angle hues in 3 tiers. Each part picks the candidate farthest from its
neighbours' colours. Colours are remembered by name, so an unrelated edit
doesn't reshuffle them.

**View changes recolour in place.** Selection, hover and solo rewrite the
overlay's colour buffer (new `recolorMesh` viewport helper) instead of
rebuilding a 480k-triangle geometry per hover. Pins redraw only when they or
the emphasised set change.

**Bugs found driving the real UI on the figurine.**
- `getSeeds()` dropped the `auto` flag, so every automatic pin got a name
  tag.
- Hover events rebuilt the action bar and wiped a half-typed merge name.
- The tool-panel shell closes on Esc. Esc is now taken in the capture phase
  only when there is a strip or selection to clear.
- The shell's height cap ignores where the panel docks, which pushed the
  footer off-screen. The panel now fits itself to the window.

The `reorder` op uses `position`, not `to`, so it doesn't collide with
reassign's `to` in the AI tool schema.
