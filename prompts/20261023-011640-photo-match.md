## Human

Implement a photo-match score: a cheap, deterministic, text-only metric that
tells an agent building a figure from a photo how close the model is and where
it is off, so most passes need no rendered image. Pure module
(`src/tools/photoMatch.ts`), a `partwright.photoMatch` browser API, a
`photoMatch` AI tool, a `model:preview --match-photo` CLI flag, tuning constants
in app config + Advanced Settings, unit tests and one e2e spec. Check it against
a Funko-style soccer-boy photo (front/back crops on black, plus a busy-blue hero
shot) and the matching code model; findings should name the known weak spots
(hair silhouette too regular/narrow, boots too small, shoulders too wide).

## Key decisions

**One pure scorer, two renderers.** The browser renders a flat REGION-ID pass
(raw ShaderMaterial into a non-MSAA render target, ids encoded in R/G, alpha 0 =
background) so labels that share a colour (white jersey/socks/shoes) stay
distinct and the ids come back bit-exact; the CLI rasterizes the same id buffer
in pure JS with the preview's camera frame. Both hand plain buffers to
`photoMatch()`, which never touches DOM/Three/config.

**Segmentation tuned on the real photos.** The black-backdrop crops have a gold
frame line and pure-black background with near-black hair. Background colour(s)
come from a k-means over a ring inside the border, skipping the outer ~1.5%
(frame) and clearing it from the mask; centres use the per-channel median and
tolerance comes from the 75th-percentile spread (a frame edge in the ring must
not inflate it). Hysteresis (half-tolerance pixels kept when connected to
confident ones) is what keeps dark hair on black; the mask is then opened,
closed, reduced to the largest component + neighbours and hole-filled.

**Region analysis = colour then space.** k-means over the photo foreground in
Lab (lightness weighted ½ for shading), seeded with the model's part colours;
parts sharing a colour split pixels by nearest model part (chamfer distance),
and pixels further than a configurable reach stay unassigned (a ball's black
patches are not hair). Area is compared as share of each silhouette so the
overall aspect error is reported once, by `aspect`/bands, not smeared into
every region. Extents use 2–98% percentiles to ignore specks.

**Findings ranking.** Band width runs (merged consecutive same-sign bands, named
by the model parts dominating them) are the most robust signal and score
highest; region area/width/height ratios are scored in log space and weighted by
part size; parts under 1.5% of the figure only get colour findings.

**Real-world finding: the front/back crops are anamorphic** (~1.6–1.8× too wide;
eyes read as wide ellipses, photo aspect 1.05 vs ~0.63 in the hero shot). Added
`pixelAspect` and `fit: 'box'` plus an aspect warning rather than silently
guessing. With `pixelAspect 0.6` the findings name the narrow hair top, the
small boots, and the over-wide lower head/torso; the busy hero backdrop shares
black and blue with the subject, which colour segmentation cannot separate —
documented, with crop/bg as the escape hatches.

**Not views-gated.** The AI tool renders offscreen but returns only text, so it
is always available (and plan-mode / retry safe); its description tells the
model to use it for routine likeness passes and look at images at checkpoints.
`overlay: true` / `--match-overlay` give a small 3-panel diff image for those
checkpoints.
