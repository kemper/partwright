## Assistant

- Reading the stored PR bodies back showed that none of the screenshots in
  #1043/#1046 ever rendered. The GitHub MCP tool code-wraps absolute URLs.
  Testing further, it also strips the `!` from image embeds, so
  `![a](/root-relative)` arrives as a plain link. That is a deliberate filter
  on images, so smuggling images past it (raw `<img>`, etc.) is out.
- What does survive is a root-relative *link*. GitHub's blob view renders a
  committed markdown file's relative images inline. So `pr:screenshots` now
  also writes a gallery page (`<stamp>-proof.md`, captions via the
  `file#caption` syntax `gh --attach` uses) next to the images on
  `pr-assets`, and prints a root-relative "View screenshots" link to it. The
  old absolute image links still print, on stderr, for channels that do
  render them.
- Verified end to end on the real PRs: re-published galleries for #1043 and
  #1046 (#1046 with new shots of params/Resize/Simplify/clip-Z from main),
  updated both bodies, and confirmed via the rendered `body_html` that each
  carries a real `<a href=…proof.md>` and that the gallery renders `<img>`s.
- Documented the why and a read-back check in CLAUDE.md. The original mistake
  was trusting the API call's success without reading the body back.
