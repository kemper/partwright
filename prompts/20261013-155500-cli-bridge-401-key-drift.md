The CLIProxyAPI integration stopped working: every attempt gives "401:

## Key decisions

**Where the error comes from**: both messages are Partwright's own wording for
a 401/403 from `GET {base}/models` — the settings modal's Test connection and
Fetch models. That request never reaches Anthropic; it's the bridge's local
client-key check. Built CLIProxyAPI v8.0.27 (current, released after its v8
config overhaul that moved client keys from root `api-keys` to
`access.api-keys`) and replayed Partwright's request against both the pre-v8
and v8 config layouts: both return 200 for the matching Bearer key and 401
"Invalid API key" / "Missing API key" otherwise. So the upgrade doesn't break
auth; the 401 means the key Partwright sends doesn't match the bridge config.

**How they drift**: setup step 2 showed a fresh random key on every modal open
and its sed one-liner only replaced the `your-api-key-N` placeholders. After
the first setup those are gone, so re-running step 2 (new browser, cleared site
data, evicted storage) was a silent no-op on the config while Partwright saved
the new key. Reproduced: re-running the old command replaced 0 keys.

**Fixes** (no new provider or transport):
- sed now also replaces earlier Partwright-generated keys (`pw-` + 48 hex), so
  re-running step 2 re-syncs the bridge. Chose this over parsing the YAML
  because it works for both layouts and leaves user-chosen keys alone.
- Once a key is saved, step 2 shows that key instead of minting another, and
  the saved key can be revealed (Show) to compare against the config.
- The 401/403 message now says whether a key was sent at all and echoes the
  server's reason, with the matching fix for each case. One shared helper
  serves both validateConnection and listModels (they had duplicated strings).

Verified against a real local v8 bridge in the browser (missing, stale, correct
key) and with a unit test for the messages.

## Review follow-ups

A review pass found that reusing *any* saved key in setup step 2 was unsafe:
a user-pasted key could carry shell/sed metacharacters into the one-liner,
wouldn't match the re-sync pattern later (bringing the drift bug back), and
would sit in plain text despite the new Show/Hide toggle. Step 2 now reuses
only keys Partwright generated (`isGeneratedApiKey`). The 401 wording is also
neutral for non-CLIProxyAPI endpoints (bridge advice as an aside). It also
picks up `detail`/`message` reasons and collapses whitespace in non-JSON
bodies. Show/Hide resets on Remove key, and the step 4 label now matches the
real button.
