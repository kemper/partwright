## Key decisions

**Where the openers live.** Panels that own their state (image paint, palette,
voxel studio, print tools, settings) register themselves next to their UI.
Tools whose state lives in main.ts (the clip plane, the Customizer, the
export/publish dialogs and the import wizards) are registered by a new
`src/ui/hostTools.ts` through a small dependency object. This keeps main.ts to
one `registerHostTools({...})` call, a few palette entries, and an extracted
`actionExportSession`, because a parallel PR is editing main.ts.

**Promise dialogs open staged via a one-shot "staged prefill".** The export
object picker, session-export options and publish modal are awaited by main.ts
actions that then download. So the opener stages a prefill in the dialog
module and runs the same toolbar action. The dialog validates the prefill
against its real choices before it builds; a rejected prefill means the
dialog never shows, so no export can follow. A pre-export "unsaved objects"
confirm can come before the picker, so openTool waits up to the new
`ui.toolDialogOpenWaitMs` setting. After that it reports the values as staged
for when the dialog opens. `objects`, `printer`, `nozzle` and `filament` are
also checked up front, so errors arrive before any confirm appears.

**Panels that save on every edit get a confirm row.** The palette manager and
print tools persist each change at once. A prefill therefore never writes
directly: it shows a violet "Suggested …" row with Apply/Dismiss (palette) or
"Use these"/Discard (print). In print tools, any user edit, or clicking Check
printability, commits what the form shows. Print tools also gained the
missing overhang-limit input, which was settable only through the API.

**Customize uses a strict validator.** The new `checkParamOverrides` rejects
unknown keys and wrong types instead of the lenient fallback that
`coerceParamValue` uses. Staging moves the sliders and re-runs the model, the
same as a drag.

**Settings focus uses `data-setting`.** A script added
`cfgKey="section.key"` to all 149 Field/ToggleField call sites, read from
their `set('section','key')` calls. focus is validated against
`APP_CONFIG_DEFAULTS`.

**"[UI] user applied …" notes.** The registry wraps each spec's `open` (rather
than editing `openTool`, which PR4's follow-up touches) to remember who
opened each tool last. Panels call `notifyToolApplied(id)` before closing. The
note is recorded only when the AI opened that tool, keeps the latest per
tool, and is capped at 6. The AI panel drains these into a leading text block
of the next user message. They are held in per-tab module memory only. Wired
for Surface, Paint, image paint, palette, voxel studio, print and customize.

**Wizards that are already open return an error rather than being replaced**,
so an AI open never discards a picked image or tuned settings.
