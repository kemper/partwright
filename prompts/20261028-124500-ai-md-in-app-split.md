## Key decisions

**Fence, don't fork.** ai.md serves two audiences. External agents
(Claude Code, the extension) read the whole file and drive the
`window.partwright` console. The in-app chat gets it as its system prompt
but calls tools. A second hand-maintained "core" file would drift, so ai.md
stays the single source. Console-only blocks are wrapped in
`<!-- external-only:start/end -->` and `inAppAiMd` strips them in
`buildSystemPrompt`, the one function every in-app consumer goes through
(chat loop, meter, both prompt viewers). A single-line `<!-- in-app: … -->`
comment carries text only the in-app model sees. Both are HTML comments, so
the served file and rendered page are unchanged for everyone else.

**What was fenced.** Each block is console-only or duplicated:
- the contents list;
- argument-validation conventions (replaced in-app by a one-line "tools
  validate their arguments" note);
- the 47K-char method listing, which no tool needs since each tool carries
  its own schema;
- the Assembly view and Arrange mode (no in-app tools);
- the iteration-workflow body, ~90% verbatim in `ai/iteration-workflow.md`.
The pointer line and "Recommended iteration pattern" stay.

**What was not.** The decision tree, topic index, objects/parts, meshOps,
api.params and paint/surface-in-code sections looked like candidates. A
line-overlap check showed they are NOT duplicated in their subdocs, so moving
them would lose information. Left in place. Result: the system prompt drops
from ~45K to ~27K tokens; turn-0 total from ~65K to ~45K. That is about −18K,
short of the plan's −30K estimate.

**Main was red.** `listExportItems`, `partAction` and `undoPartEdit` merged
from the Parts work while #1177 was in flight, so the new "every tool is in a
group" test failed on main. They go in the `objects` group (object/part
management and export splits).

The budget ceiling for the system prompt drops from 168K to 104K chars.
`tests/unit/aiMdInApp.test.ts` keeps the markers balanced and pins what each
audience gets.
