## Key decisions

**Fix it once, in `commitSurfaceModifier`.** Every bake (surface textures,
scale / rotate / place in bake mode) commits through it, so one change covers
them all. It also covers code-built models: `api.label` parts were dropped by
a bake for the same reason, since the code that declared them is replaced.

**Store the parts on the baked import, not in code.** The run's labels become
`ImportedMesh.parts` on the baked mesh, and the generated
`Manifold.ofMesh(api.imports[0])` is rewritten to `api.importWithParts(0)` —
the same mechanism `acceptParts` uses, so labels, paint scopes and the object
rail work unchanged and the parts persist with the version.

**Carry by triangle list when it's shared, by position otherwise.** A rigid
transform keeps the triangle list but moves every triangle, so position
matching would fail; a texture re-tessellates in place, so position matching
is right — to the nearest *surface*, not the nearest centroid
(`remapTriangleSets`): a model's few large triangles (a cube's faces) have
centroids far from most of their surface, and centroid matching handed most
of the cube to the knob sitting on it. The label map indexes the run's own
mesh, which can differ from the displayed one, so it's mapped onto the bake's
input first.

**Parts keep their code colours.** A part takes its `api.label` colour when
the bake keeps colour (`preserveColor`), so the rail and paint scopes still
show it; with colour off the parts carry no colour either.
