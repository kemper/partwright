## Key decisions

**Ordering: SES lockdown → engine init → workerLockdown audit.** The spike's
"before-init" order, so no engine glue ever initialises against unfrozen
intrinsics, and the #1119 audit runs last so it sees what SES installed. The
`init` message now carries `ses: boolean`; the Worker treats anything but an
explicit `false` as ON, so a Worker can only run unsandboxed when the trusted
app asked for it, and a request racing ahead of `init` still gets SES first.

**SES globals are allowlisted, not default-denied.** SES installs `lockdown`,
`repairIntrinsics`, `hardenIntrinsics`, `harden`, `Compartment`, `assert` and a
registry symbol for its AVA console hook. All capability-free and unreachable
from model code; letting default-deny strip them would work too, but would put
six "unknown capability" names into the debug line that exists to surface new
browser APIs. The audit test now inspects the realm from the engine side (a
dev-only `inspect_realm` message), because model code can no longer name the
Worker global.

**Install-once wrappers, then harden the whole per-run `api`.** Rather than
hand-listing namespace singletons, each engine calls `hardenModelShared(api)`
(SES `harden`, identity without SES) before compiling, so everything reachable
from that run's api is frozen. That required the manifold-3d tracking wrappers
and primitive guards to be installed once, reading the active run's tracker
from a module variable. The replicad engine exposes `Manifold` too, so it calls
`ensureManifoldRunWrappers()` first (a replicad run followed by a manifold-js
run in one Worker would otherwise find the classes already frozen and silently
lose allocation tracking and the guards).

**Proving it: a stamp test instead of a fixed list.** Run 1 stamps every
writable object reachable from `api` and from what common api calls return;
run 2 reports any stamp it finds. This found holes the spike's api-only walk
could not see:
- `Mesh` (getMesh() results) and embind's `$$.ptrType` descriptors — hardened
  via probe instances at wrapper install.
- **`BrepShape._shape.oc` exposed the entire OpenCASCADE Emscripten module**
  (embind classes, HEAP views, `_malloc`, `FS`, `dynCall_*`) — mutable by
  Emscripten itself, so it can't be hardened. Escalation candidate; resolved
  instead by moving the replicad shape and label data into a module-private
  WeakMap (`isBrepShape()` replaces the `'_shape' in x` checks). This is an
  engine-internal refactor with no API change (the `_` fields were never
  documented), and it also stops look-alike objects posing as BREP shapes.
- **The original (pre-lockdown) `Error` constructor**, reachable through any
  engine error class (`ValidationError extends Error` is evaluated before
  lockdown). lockdown replaces `globalThis.Error` but leaves the original
  unfrozen, and it holds V8's live `prepareStackTrace` hook; verified that
  model code could install a realm-wide stack hook that intercepts every later
  error (no global leaked in the probe since all frames were strict, but it's a
  hole). Fixed by hardening the original Error/Date/RegExp after lockdown
  (fail closed if not frozen), plus `ValidationError` and `Blob`.

**Error UX: our own Lezer pass instead of SES's `__evade*` options.** The
evade options rewrite string literal *contents* and turn a real `import(` into
a call to an undefined `__import__` that fails later with a confusing message.
`neutralizeSesRejections` rewrites only comments (length-preserving) and
literal text (hex escapes — value unchanged, and a syntax error outside a
literal, so a parser disagreement can't create working code); real
`import()`/`eval()` still fail at compile time with "rejected on line N" and a
hint. The wrapper head now shares the user's first line, so there is no line
offset to correct; `modelLineNumber` tells sourceDiagnostics the line is
already the user's.

**Endowments.** Math/Date from the start compartment, Float16/32/64Array,
forwarding `console`, `performance.now()` only. Catalog + examples use only
Math/Map/Set/Array/String/Number/Object/Error/Float32Array/parseInt/Infinity.
Timers are deliberately not endowed: their callbacks would outlive the run.

**Dev-server reloads.** `ses` is imported lazily from the Worker, which Vite's
start-up dep scan doesn't follow, so its runtime discovery reloaded the page
mid-test on a cold cache; added it to `optimizeDeps.include`.

**Skipped: lockdown in Node `model:preview`.** Locking down the Node/Vite SSR
realm would freeze the SSR runtime's own intrinsics; not cheap. Documented as a
parity gap.
