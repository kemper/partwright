## Human

Asked whether the in-app AI agent could cut cost by having a frontier model delegate to cheaper workers — a hard Opus session (making a mask from an existing mesh) had cost about $50. Shared the AI Call Log, which had cleared on a reload: a 310 s / 29,708-token High-thinking step followed by a step with zero cache reads. Then reported a turn stuck at "$1.43 · 32768t out · 376.3s" that ended with "Response was cut off … Keep going to let it continue from where it left off". Asked to open an issue, do the PR and get it merged, and also to default the reasoning level to Medium.

## Assistant

## Key decisions

**Measure first, then fix the real leaks.** The log showed the money going to thinking output and to the prompt cache expiring, not to the model's per-token price. A cheaper worker model is still worth building, but it's tracked as later work on #1206. This PR covers the four leaks the log exposed, plus the Medium default.

**Why the cache missed.** The 310 s think outlived Anthropic's 5-minute cache, so the next step re-wrote ~158k tokens at 1.25× input. High/XHigh/Max turns now use the 1-hour TTL (2× input to write). One TTL per request, because the API needs longer-lived breakpoints before shorter ones. It's gated on thinking level so short Medium/Low steps keep the cheaper 5-minute writes. There's an Advanced setting to turn it off.

**"Keep going" was misleading after a thinking cut-off.** The thinking is dropped from history, because an assistant turn can't end in thinking, so the step restarts rather than continues. A max_tokens stop with no text and no tool call now gets its own outcome detail. The notice says the step will restart and leads with "Retry at <one lower level> thinking".

**Call log.** It now records cache writes (with the 1-hour part) and per-call cost, through one `usageEventFields` helper shared by the chat loop, review and compaction. It's mirrored to sessionStorage, not IndexedDB: per tab, gone when the tab closes, so no cross-tab bleed and request fragments don't persist long-term.

**Medium default migration.** Any toggle change, even switching model, marks the preset Custom. So "Standard + High" can't tell an explicit High pick from the old default carried along. Settings rev 2 lowers any stored pre-rev-2 High once. Picks made after that, High included, are kept. Full's XHigh is untouched.

## Assistant

## Review follow-up

A review pass over the diff found three real gaps in this PR's own code. All fixed in this push:
- **The cut-off notice is limited to steps that actually thought.** A Local model's truncated tool call also arrives as max_tokens with no text and no tool call, and had been mislabelled "ran out of room while thinking", which also hid the existing Local hint.
- **Session-saved toggle snapshots now carry the settings rev.** Opening an older session restores its snapshot, so a snapshot without a rev and set to High is lowered to Medium using the same rule. Otherwise reopening a session would have brought High back as if it were a deliberate pick.
- **"Retry at lower thinking" only changes the level once the resume goes ahead.** It now runs after the in-flight, owner and spend-cap checks, so a rejected click doesn't quietly rewrite the session's setting. The retry level is also taken from the level the step ran at, recorded when the notice is shown.
